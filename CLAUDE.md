# Collab — Real-time Collaborative Whiteboard

Next.js + Express + Socket.IO app (package name internally is `board_t`). Users create/join a room and draw together on a shared canvas in real time, with live cursors, chat, an undo/redo history per user, an opt-in AI teammate ("Sketch") that draws in the room, and a Rewind panel that scrubs the board's history.

## Architecture

- **Custom server**, split into small modules under `server/`:
  - `index.ts` — bootstrap only: parse config, prepare Next, listen.
  - `app.ts` — `createAppServer`, which wires Express, the HTTP server, Socket.IO and the `RoomStore`. It takes the Next request handler as an argument, which is what lets tests boot the whole server without Next.
  - `config.ts` — env parsing with Zod at startup. Beyond the Phase 0 timing values it holds the AI flags, `STORAGE`/`DATABASE_URL`/`PGLITE_DIR`, `REDIS_URL`/`NODE_ID`, the object-storage set (`UPLOADS_DIR`, `S3_*`, `PUBLIC_URL`), snapshot tuning, and the auth set (`AUTH_SECRET`, provider pairs, `AUTH_DEV_LOGIN`). `resolveStorage(config)` picks the storage mode. Full table in `docs/operations.md`.
  - `rooms/RoomStore.ts` — all live room state in memory, with no Socket.IO dependency. Still the source of truth for every loaded room; also `hydrate` (rebuild from a persisted record, with an optional snapshot image move first), `reattribute` (guest → account), `peekLastMove`, `rename`, `appendChat`.
  - `boards/BoardStore.ts` — what handlers and Sketch talk to: `RoomStore` plus a `Persistence` port (`boards/persistence.ts`). `ensureLoaded(roomId)` hydrates a cold room before `check_room`/`join_room`/`rejoin_room`; every stored move, undo, removal, rename and chat line is recorded fire-and-forget; `create` is awaited. `boards/dbPersistence.ts` is the Postgres implementation (buffered, ordered, one transaction per flush, `board_moves` for current state plus append-only `board_ops`); `boards/createPersistence.ts` builds it from config. `boards/routes.ts` is the REST API (`/api/boards`, share links, `/api/join/:token`, `/api/templates`); `boards/templates.ts` authors templates as drawing programs; `boards/shareLinks.ts` mints and redeems invitations.
  - `db/schema.ts` (Drizzle), `db/client.ts` (`pg` for Postgres, PGlite embedded; one `Db` type), `db/migrations/` applied at startup. `npm run db:generate` after a schema change.
  - `auth/` — `guestCookie.ts` (signed `collab_guest`), `session.ts` (Auth.js JWT from a cookie header), `authConfig.ts` (`@auth/express` with the Drizzle adapter, Google/GitHub/dev-login), `routes.ts` (`/api/auth/*`, `/api/me`, `/api/me/guest`, `identityFromRequest`), `mergeGuest.ts`, `roles.ts`/`dbRoles.ts` (`RoleResolver`: memory rule or memberships + visibility, cached 30 s).
  - `storage/` — `ObjectStorage` port: `local.ts` (files under `UPLOADS_DIR`, served at `/uploads`, HMAC-signed presigned PUTs to `/api/uploads/put`) and `s3.ts` (R2/MinIO); `routes.ts` for presign and PUT.
  - `render/` — `renderBoard.ts` draws moves on a `@napi-rs/canvas` with the browser's `drawMove`; `nodeLoader.ts` is the server image loader. `jobs/snapshots.ts` renders snapshots every `SNAPSHOT_EVERY` moves and thumbnails after a quiet period, only when a database exists.
  - `redis.ts` — optional clients; with `REDIS_URL`, the Socket.IO Redis adapter and `RateLimiterRedis` are on. `ops/health.ts` (`/healthz`, `/readyz`, `/metrics`) and `ops/metrics.ts` (prom-client).
  - `socket/identity.ts` — handshake middleware. `socket/handlers.ts` — every event; takes `HandlerDeps` (`ai` service or null, and the `features` payload sent once per connection). `socket/safeHandler.ts` — the try/catch wrapper each handler is wrapped in. `socket/rateLimit.ts` — per-user budgets.
  - `ai/` — Sketch. `index.ts` (`createAiService`: returns null unless `AI_ENABLED` and an agent exists; queue, per-room limits, status broadcasts, requester-only undo), `schema.ts` (the DrawingProgram the model emits, strict plus a loose output-format copy), `interpreter.ts` (program → planned moves with cursor paths and durations; `placeTarget` per kind), `participant.ts` (the synthetic room member: cursor animation on timers, live strokes for lines, `RoomStore.addMove` with `meta.requestId`), `agent.ts` (Anthropic), `openaiAgent.ts` (OpenAI), `fakeAgent.ts` (fixed programs for `AI_FAKE=1` and tests), `prompts.ts`, `limits.ts`, `queue.ts`. Reference: `docs/ai-teammate.md`.
  - `logger.ts` — pino. Server code uses this, not `console` (lint enforces it).
  - Next.js pages/API are NOT used for real-time logic. Dev runs via `tsx watch server/index.ts`, not `next dev`.
- **Identity is a stable `userId`**, not `socket.id`. A guest is the browser's uuid from `localStorage` (`common/lib/identity.ts`), sent with `PROTOCOL_VERSION` in the handshake and mirrored into the signed `collab_guest` cookie by `POST /api/me/guest` so HTTP routes know the guest too. A signed-in user is an Auth.js JWT session: the handshake trusts the session cookie first, uses the account id, and treats the uuid the client sent as a guest to merge (`mergeGuest` + `RoomStore.reattribute`). The server answers every connection with `identity`; the client adopts that id (`setMyUserId`) so "me" agrees with the server. A guest handshake presenting an account id is refused with `identity_taken` and the client mints a fresh id. `server/socket/identity.ts` refuses older protocols too.
- **Rooms** are held in memory: `Map<roomId, ServerRoom>`, keyed by `userId` throughout, and recorded through the persistence port when storage is on (`STORAGE=pglite` embedded, `DATABASE_URL` hosted; memory only by default, lost on restart). A cold board is rebuilt from `boards`, `board_moves` (after the latest snapshot) and the last 100 `chat_messages`; the snapshot is a synthetic image move by `system:snapshot` at its sequence number so renderers need no special case. Room cap: 12 humans. Room ids are 8 base64url characters from `randomBytes(6)`. `RoomUser.synthetic` marks server-driven members (Sketch, id `ai:sketch` from `common/constants/ai.ts`): exempt from the cap, never offline, and not counted when deciding a room is empty (`humanCount`). `toPublicUser` and `isOffline` both honour it. `ServerRoom` also carries `title`, `ownerId`, `chat`, `snapshotSeq`.
- **Roles** (`common/constants/roles.ts`): owner, editor, commenter, viewer, none. Handlers check them (`draw`/`undo`/`ai_request` editor+, `send_msg` commenter+, `rename_room` owner, joins viewer+) and answer `denied(action, role)` rather than staying silent; `joined` carries `{ role }` or `{ reason }`. Memory mode: creator owner, everyone else editor. Database mode: membership row, then visibility (`link` grants `linkRole`, default editor; `private` grants nothing). Share links (`/join/<token>`) grant a role and never downgrade.
- **Presence has three states, not two.** A dropped socket calls `markOffline`, which holds the user's place — colour, moves, undo history — for `USER_GRACE_MS` and broadcasts `user_offline`. `user_disconnected` fires only when that window expires. `rejoin_room(roomId, lastSeq)` reattaches and replies with `room_delta`: just the moves after the sequence number the client reported. Empty rooms are stamped with `emptySince` and swept after `ROOM_GRACE_MS`.
- **Move-based drawing model**: every stroke/shape is a `Move`. The server owns `id`, `timestamp`, `seq`, `userId` and the optional `meta` (an AI `requestId`); the client supplies `clientId`; `drawPayloadSchema` omits the server-owned fields so a client cannot forge them. `seq` is monotonic per room and is what clients sort by, so two clients render the same picture — `timestamp` is only a fallback for moves that have not been through the server. A repeated `clientId` is recognised as a resend and not stored twice, which makes a retry safe. `drawed` holds moves from users who left, so their drawing survives them; those moves keep their `userId`, which is what lets Rewind filter by a departed author. Shapes: `line`, `circle`, `rect`, `image`, `text` (`text: { content, fontSize }`, anchored at `path[0]`, drawn with `fillText` in Montserrat; font size derives from the line-width slider via `common/render/text.ts`). `RoomStore.removeMoves(roomId, ids)` plus the `moves_removed` broadcast remove arbitrary moves everywhere; it is how "Undo Sketch" works.
- **Client render pipeline uses three stacked canvases**, not one, kept separate specifically so each layer's own clear-and-redraw loop can't wipe another's content: a committed canvas (z-10, the `CommittedRenderer` below), a remote-live canvas (z-15, other users' in-progress strokes), and a local-live canvas (z-20, this user's own in-progress stroke). `useMovesHandlers` merges `movesWithoutUser + myMoves + all other users' moves` with `sortMoves` (`common/render/historyView.ts`), passes the result through `visibleMoves(sorted, historyView)` — live with no filter this returns the same array — and feeds the committed canvas; a small `Minimap` canvas mirrors the main canvas + background.
- **`CommittedRenderer`** (`modules/room/render/CommittedRenderer.ts`) is a checkpoint-bitmap renderer for fast undo on large boards: it keeps a `createImageBitmap` snapshot plus a tail of moves since that snapshot, and replays only the tail instead of every move from scratch. Scheduling is rAF-coalesced via a `frameScheduled` boolean set *before* calling `requestAnimationFrame` — setting it from the callback's return value instead is a real bug that silently drops every `schedule()` call after the first synchronous callback.
- **Drawing interaction**: `useDraw` (in `modules/room/modules/board/hooks/`) owns the live pointer-down/move/up flow via the Pointer Events API (unifying mouse/touch/pen), writing directly to the local-live canvas via helpers in `helpers/Canvas.helpers.ts` (`drawLine`, `drawCircle`, `drawRect`) before committing a finished `Move`. `mode: 'select'` reuses the same drag flow to define a selection rectangle (used for the image/move overlay) instead of drawing. The text tool (`shape: 'text'`, hotkey `T`) is click-to-place: `useDraw` commits any open box and opens a new one through `modules/room/modules/board/lib/textTool.ts`, which owns the state machine outside React; `TextInput.tsx` is the editor (Enter commits, Shift+Enter breaks, Escape cancels, blur with text commits). A pointer-up with no stroke in progress sends nothing. Drawing and undo are refused while Rewind is showing the past (`isViewingHistory()`). `useLiveStrokeBroadcast`/`useLiveStrokes` stream in-progress strokes to other clients (`stroke_start/points/end` → volatile, unstored server relay → `live_stroke_start/points/end`) so remote strokes appear before the drawer lifts the pointer; `strokeId` is the same value as the eventual move's `clientId`.
- **Viewport**: `common/store/viewport.store.ts` holds pan/zoom/hand-tool state and is applied as a CSS `transform: translate(x,y) scale(scale)` on a wrapper div — canvas pixel dimensions stay fixed at 4000×2000. `common/lib/coords.ts` (`toBoard`/`toScreen`) converts between board and screen space. `useViewportBroadcast` relays viewport changes for follow mode; `cursor`/`summon` events (also volatile, rate-limited server relays) drive remote cursors and "bring everyone to your view".
- **Validation lives in `common/schemas/`** (Zod 4) and is shared by client and server. **These schemas are the source of truth for the drawing types**: `Move`, `CtxOptions`, `Shape` and `CtxMode` are `z.infer` outputs that `common/types/global.d.ts` re-exports, so the validated wire shape cannot drift from the compile-time type. `common/schemas/ai.ts` holds the AI request schema. The server validates every inbound payload and drops what fails.
- **Feature flags come from the server.** `config.ts` parses `AI_ENABLED`, `AI_FAKE`, `AI_PROVIDER`, `ANTHROPIC_API_KEY`/`AI_MODEL`, `OPENAI_API_KEY`/`OPENAI_MODEL`, `REWIND_ENABLED` (booleans via `z.stringbool()`). The server sends a `features` event once per connection (`ai`, `rewind`, `auth`, `persistent`, `node`); the client stores it in `common/store/features.store.ts` and components read `useFeatureFlag(...)`. The listener is registered beside the socket in `common/lib/socket.ts`, not in a React effect: on localhost the handshake completes before hydration, so an effect misses the one-time event. With a flag off, the corresponding UI does not render at all. `identity` is handled the same way.
- **Images travel as URLs.** `img: { url, width, height }` after a presigned upload (`common/lib/uploads.ts` → `POST /api/uploads/presign` → PUT); `img.base64` is still accepted and the server offloads it to storage and rewrites the move before storing. `drawMove` takes an image loader so the same code renders in the browser and on the server.
- **HTTP lives on Express, not Next API routes.** Every database connection belongs to the custom server (PGlite is single-process), so Auth.js, uploads, boards and ops are Express routes registered in `app.ts` before the Next catch-all; Next pages (`/boards`, `/join/[token]`) are client-rendered shells over `/api/*`.
- **Sketch on the client**: `modules/room/lib/ai.ts` (`requestSketch` mints a `requestId`, marks it as ours in `common/store/ai.store.ts`, and emits `ai_request` with the visible board rect; `parseSketchMention` for `@sketch`), `modules/room/lib/captureBoard.ts` (PNG of a board region, background included, fitted to 1024 px via `common/lib/resizeImage.ts`), `useAiSync` (applies `ai_status`, toasts only for our requests, "Undo Sketch" action emits `ai_undo`), `SketchPopover` in the toolbar, the sparkle button on the selection bar, Sketch items in the palette, a pulsing avatar ring and a cursor label while a request is active.
- **Rewind** (`modules/room/modules/rewind/`): `history.store.ts` carries `view` (`cursorSeq` null = live, `userFilter`, `playing`, `speed`, `panelOpen`); `RewindPanel` (top-bar clock or `Cmd+Shift+H`) has the scrubber, playback (`useRewindPlayback`), author chips ("Former participant" for departed users, Sketch by name), Live, and a timelapse export (`useTimelapseExport`: offscreen replay under `MediaRecorder` + `captureStream`, appending moves per frame because draws, erasers included, are additive). `HistoryBanner` marks the read-only state. No renderer changes were needed: scrubbing forward appends onto the checkpoint, scrubbing back past it triggers a full replay.
- **State split**: Zustand stores per concern under `common/store/`:
  - `room` — the current `ClientRoom` (users, moves, my moves)
  - `options` — active tool `CtxOptions` (color, line width, shape, mode, selection)
  - `background` — canvas background setting
  - `history` — the redo stack (moves popped by undo, replayed on redo)
  - `drawing`, `viewport`, `liveStrokes`, `presence` — in-progress draw state, pan/zoom/hand-tool, remote live-stroke buffers, and cursor/online state, respectively
  - Reactive reads use the hook form (`useXStore((state) => state.y)`); hot-path/non-reactive code (drawing, viewport math) reads and writes imperatively via `getState()`/`setState()` instead of subscribing.
- **Socket contract** is fully typed in `common/types/global.d.ts` (`ClientToServerEvents` / `ServerToClientEvents`) and shared by client (`common/lib/socket.ts`) and server. Key events: `create_room`, `join_room`, `check_room`, `joined_room` (full snapshot), `rejoin_room`/`room_delta` (resume after a reconnect), `draw`/`your_move`/`user_draw`, `undo`/`user_undo`, `moves_removed`, `stroke_start`/`stroke_points`/`stroke_end`/`live_stroke_start`/`live_stroke_points`/`live_stroke_end`, `cursor`/`viewport`/`summon`, `send_msg`/`new_msg`, `user_offline`/`user_online`/`user_disconnected`, `rate_limited`, `features`, `ai_request`/`ai_undo`/`ai_status`. `PROTOCOL_VERSION` is 2 (Phase 2); the legacy `mouse_move`/`mouse_moved` relay is gone.
- **Modules layout** (`modules/`) mirrors feature areas, each with its own `components/`, `hooks/`, `index.ts` barrel:
  - `home` — landing page (create/join room form, link to `/boards` when storage is on)
  - `boards` — the dashboard (`pages/boards.tsx`): templates, cards with thumbnails, rename, duplicate, star, delete against `/api/boards`
  - `room` — room shell, name-entry gate (`NameInput`), `TopBar` (board name, user list, share), `CommandPalette` (⌘K), `ShortcutsSheet` (`?`); contains sub-modules:
    - `board` — the three-layer canvas, minimap, cursor broadcaster/layer, moved image, selection bar, zoom controls, plus `render/CommittedRenderer`
    - `toolbar` — tool/shape/color/line-width pickers (shadcn/Radix `ToggleGroup`/`Popover`/`Slider`), background picker, undo/redo, share modal, global tool hotkeys (`useToolHotkeys`); `ToolbarActionsContext` mounts the shared image-paste listener exactly once so multiple consumers (toolbar, command palette) don't double-register it
    - `chat` — in-room chat panel; a message starting with `@sketch` is also an AI draw request when the flag is on
    - `rewind` — the history panel and banner
  - `modal` — generic modal manager (Zustand-driven, Framer Motion animated, used for "room not found", background/share modals)
- **shadcn/ui primitives** live in `common/components/ui/` — Radix UI wrapped with `cn()` (clsx + tailwind-merge), CSS-variable-based theme tokens. `HotkeyTooltip` (`common/components/HotkeyTooltip.tsx`) composes `Tooltip` + `Kbd` around a toolbar control; because Radix `Tooltip.Trigger asChild` and the wrapped control can both want to own `data-state` on the same DOM node (Tooltip's wins), style any wrapped control's own active/selected state off a different attribute (e.g. `aria-checked`), not `data-[state=on]`.

## Conventions

- Path alias `@/*` → project root (see `tsconfig.json`). `module: esnext`, `moduleResolution: bundler`, `target: ES2017`.
- Strict TypeScript. ESLint flat config in `eslint.config.mjs` with **Airbnb + Airbnb TypeScript + Airbnb hooks, the Next presets, Tailwind, and Prettier all active**, plus `unused-imports`. Overrides worth knowing: config files and `server/testing/**` may import devDependencies, and `no-console` is *not* disabled for the server — use the pino logger.
- Server code imports within `server/` relatively, and runtime code from `common/` through `@/`. That works because `tsup` bundles; `tsc` would emit an unresolvable `require("@/...")`.
- Tailwind CSS v3.4 (`darkMode: 'class'`), custom font-size scale, Montserrat font family, content globs cover `pages/`, `common/`, `modules/`. Staying on 3.4 for now — see the Tailwind 4 decision record in `docs/roadmap/phase-1-canvas-and-presence.md` (Step 9): the Tailwind-4-compatible `eslint-plugin-tailwindcss` major requires ESLint 9/10, which this repo's Airbnb-based ESLint 8 setup doesn't support yet.
- Framer Motion for modal animations only; the toolbar (Step 8) moved to shadcn/Radix primitives instead. Use `MotionValue.on('change', …)`, not the deprecated `.onChange()`.
- Sonner (`sonner`'s `toast()` / `<Toaster />`) for join/leave notifications and rate-limit warnings — not `react-toastify`, which is blocked by an ESLint `no-restricted-imports` rule alongside `react-icons` (use `lucide-react` for icons).
- `lucide-react` for icons; `react-icons` is blocked by the same rule.
- Zustand state is replaced, never mutated in place — copy Maps and arrays before changing them and pass the copy to `set()`, or a component reading the same reference can skip a re-render.
- `cmdk` (via `common/components/ui/command.tsx`) backs the command palette.

## Build/run

- `npm run dev` — `tsx watch server/index.ts` (the actual dev entrypoint, not `next dev`). `STORAGE=pglite npm run dev` keeps boards across restarts with no database server; `npm run dev:infra` starts Postgres/Redis/MinIO from compose for the hosted-style setup
- `npm run db:generate` / `npm run db:migrate` — Drizzle migrations
- `npm run build` — `tsup` bundles the server to `build/index.js`, then `next build`
- `npm start` — `NODE_ENV=production node build/index.js`
- `npm run lint` — `eslint .`
- `npm run typecheck` — `tsc --noEmit`
- `npm test` — Vitest: `RoomStore` unit tests, socket integration tests (including the AI pipeline with the fake agent), schema tests, a seeded fuzz test, renderer pixel tests on a Node canvas (`@napi-rs/canvas`), agent tests with scripted SDK clients, and client hook/store tests
- `npm run test:e2e` — Playwright, two browser contexts against a real dev server, started with `AI_ENABLED=1 AI_FAKE=1 STORAGE=pglite` so the Sketch and dashboard specs run without a key or a database server
- `AI_ENABLED=1 AI_FAKE=1 npm run dev` — the app with a deterministic Sketch, no key needed
- Node 22 (`.nvmrc`). CI runs lint, typecheck, unit tests, a production build, and the e2e suite.

## Testing notes

- Unit and integration tests run on the `node` environment; files needing a DOM opt in with `// @vitest-environment jsdom`.
- Database tests use PGlite in memory (`createPglite()` with no directory): real Postgres SQL, no daemon. Two servers can share one in-memory `Database` inside a process, which is how the restart and two-node tests work. `server/redis.test.ts` spawns a local `redis-server` when the binary exists and is skipped otherwise; CI provides `TEST_REDIS_URL`/`TEST_DATABASE_URL` from service containers.
- Auth.js is exercised for real in `server/auth/auth.test.ts` through the dev-login provider (`/api/auth/csrf` → `/api/auth/callback/dev`); the socket handshake test mints a JWT with `encode` from `@auth/core/jwt`.
- Socket tests boot the real server via `createAppServer` with a stubbed Next handler, and each client presents its own `userId` in the handshake.
- Tests that exercise grace windows pass millisecond values through `config` rather than using fake timers — real sockets and fake timers do not mix.
- `safeHandler` catches handler throws, which means a "does not crash" test can pass against genuinely broken code. Tests covering guarded paths also assert `logger.error` was never called; that is the only externally visible difference between a clean early return and a swallowed exception.
- AI tests shrink the animation (`aiOptions.timing`, `aiOptions.participant.tickMs`) and limits through `createAppServer({ aiOptions })`; never rely on default timings in a test.
- Playwright text assertions on chat content need `toHaveCount(2)`: every chat message renders twice, once in the panel and once as a bubble by the sender's cursor.

## Known gotchas / things to watch for

- With `STORAGE=memory` (the default) a server restart wipes all rooms. With storage on, the in-memory room is a cache of the record: writes are buffered (50 ms / 50 items) and a batch that fails three times is dropped with an error log and a metric, so a database outage never blocks drawing but can lose the last moments of work.
- PGlite is single-process: never point two processes at one `PGLITE_DIR`. It also needs its parent directories created (`createPglite` does `mkdir -p`).
- Room state is per node. With `REDIS_URL` broadcasts and rate limits are shared, but a room split across nodes does not share presence or sequence numbers live. Documented as deferred in the Phase 3 decision record.
- `board_ops` is append-only history; `board_moves` is the current board. Undo/remove delete from `board_moves` and append to `board_ops`. The sequence resumes from the highest number in `board_ops`, so an undone move's number is never reused.
- Undo/redo is per-user and client-driven (`savedMoves` atom holds the redo stack); the server only tracks moves for replay and leave-persistence, not a global undo stack. Redo re-sends the move with a **fresh** `clientId`, since reusing the old one would be dropped as a duplicate. "Undo Sketch" is different: it is server-side removal by `meta.requestId`, requester-only, broadcast as `moves_removed`.
- Socket.IO volatile emits are dropped whenever the transport's previous write has not flushed. Two volatile emits in the same tick lose the second one almost every time. Sketch's `live_stroke_*` events are therefore not volatile; human cursor/stroke relays are, because they come from separate client intervals.
- The model is constrained to the loose `drawingProgramOutputSchema`; the strict `drawingProgramSchema` runs afterwards with one repair retry. Structured output formats enforce structure, not numeric ranges or patterns.
- The room snapshot carries this client's own moves under its own id. They must be split into `myMoves`, or the strokes render but undo does nothing.
- Never put internal `RoomUser` fields on the wire — use `toPublicUser`. The record holds a live timer handle that JSON would mangle.
- Rate-limit budgets are keyed by `userId` and are deliberately **not** cleared on disconnect; clearing them would let a throttled client reset its budget by reconnecting.
- Keyboard shortcuts live in `common/lib/keyboard.ts` and accept Cmd or Ctrl. Anything bound to `document` must check `isTypingTarget(e.target)` first, or it will fire while the user types in chat.
- The 1.5 MB base64 image cap is enforced client-side *before* a selection is erased in `useSelection`, because the delete lands immediately while the image is only sent when the user drops it.
- `next build`'s own ESLint step is disabled (`eslint.ignoreDuringBuilds`): Next 15's runner passes eslintrc-era options that ESLint 8 rejects once a flat config exists. Linting happens in its own CI job.
- Do not pipe a long-running server through `head` (`npm run dev | head -40`). `head` exits after N lines and the server then stalls on a broken pipe, which looks exactly like the app hanging.
- macOS's filesystem is case-insensitive: `modules/room/modules/toolbar/components/ToolBar.tsx` and a hypothetical `Toolbar.tsx` are the same file on disk even though git tracks the casing. Writing a "new" file with different casing than an existing one silently overwrites it in place. Keep using the existing casing (`ToolBar.tsx`) rather than fighting a case-only rename.
- Two browser tabs in the same Chrome profile share `localStorage`, so they get the same `userId` — for manual multi-user testing, force a distinct identity in one tab first: `localStorage.setItem('collab:userId', crypto.randomUUID())` then reload.
- A client joining a room after other users are already present does not see those existing users in its own avatar list (the reverse direction works via the `new_user` broadcast). Pre-existing bug, not yet fixed.
